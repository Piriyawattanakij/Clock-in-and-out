# Clock-in-and-out

ระบบบันทึกเวลาเข้า-ออกงานของพนักงาน โดยพนักงานต้อง**อยู่ในพื้นที่ร้าน** (ตรวจตำแหน่งจาก GPS ของมือถือ) จึงจะบันทึกเวลาได้ พร้อมระบบคิดเงินเดือน

ทำเป็น Web App เปิดผ่านเบราว์เซอร์บนมือถือได้ทันที ไม่ต้องติดตั้งแอพ
หน้าจอออกแบบสำหรับมือถือเป็นหลัก มีเมนูด้านล่างแบบแอพ และรองรับโหมดมืด

**ติดตั้งเป็นแอพบนหน้าจอโฮม:** iPhone (Safari) กด "แชร์" → "เพิ่มไปยังหน้าจอโฮม" / Android (Chrome) กดเมนู ⋮ → "เพิ่มลงในหน้าจอหลัก" 

## ความสามารถ

**พนักงาน**
- บันทึกเวลาเข้า/ออก โดยระบบตรวจว่าอยู่ในรัศมีของร้านหรือไม่ (ตรวจที่ server)
- ดูประวัติการทำงานแบบปฏิทินรายเดือน (สีบอกสถานะ: มาทำงาน/สาย/ขาด/ลา/วันหยุด) แตะวันที่เพื่อดูเวลาเข้า-ออก ชั่วโมงทำงาน สาย OT
- ขอลา (ลาป่วย/ลากิจ/พักร้อน/ไม่รับเงิน) ดูสิทธิ์ลาคงเหลือของปี และยกเลิกคำขอได้
- ยืนยันวันทำงานของงวดเงินเดือน (เปิดให้ยืนยันตั้งแต่วันสุดท้ายของงวด) หรือแจ้งแก้ไขถ้าข้อมูลผิด
- ดูและพิมพ์สลิปเงินเดือน (เฉพาะงวดที่อนุมัติแล้ว)
- เพิ่ม/เปลี่ยนรูปโปรไฟล์ของตัวเอง (ถ่ายจากกล้องหรือเลือกจากเครื่อง) แสดงที่หน้าบันทึกเวลา
- เปลี่ยนรหัสผ่านเองได้ที่หน้าบัญชี (ต้องกรอกรหัสเดิม) และเมื่อผู้ดูแลตั้ง/รีเซ็ตรหัสให้ จะต้องตั้งรหัสใหม่เองตอนเข้าใช้ครั้งแรก
- อ่านประกาศจากร้าน: กระดิ่ง 🔔 ที่หน้าแรกแสดงจำนวนประกาศที่ยังไม่ได้อ่าน

- **รางวัล (กระปุก KICHI)**: สะสม badge สไตล์ญี่ปุ่นจากการทำงาน (ขยันเต็มเดือน, ตรงเวลา, ฮีโร่แทนกะ, streak, ครบรอบ ฯลฯ) กดรับพร้อม effect (สะสมพลัง → ระเบิดแสง → เหรียญหมุน → ตัวเลขนับขึ้น) หมุนดูเหรียญแบบ 3 มิติ และแชร์เป็นรูปภาพ (1080×1350) ไป Facebook / IG / LINE หรือบันทึกรูปได้ เงินรางวัลสะสมไว้แลกเป็นก้อนทีหลังได้ (ขั้นต่ำ 500 บาท)

**ผู้ดูแลระบบ (Admin)**
- ภาพรวมวันนี้: ใครมาแล้ว, กำลังทำงาน, มาสาย
- จัดการข้อมูลพนักงาน: รูป, ร้าน, กะ, วันเริ่มงาน, ประเภทค่าจ้าง, ประกันสังคม, บัญชีธนาคาร
- จัดการร้าน/สาขา: พิกัด + รัศมี (กด "ใช้ตำแหน่งปัจจุบัน" ขณะยืนในร้านได้)
- กะงาน (รองรับกะข้ามวัน), วันทำงานในสัปดาห์, วันหยุดนักขัตฤกษ์
- อนุมัติ/ไม่อนุมัติคำขอลา (พร้อมหมายเหตุ) และดูตารางวันลารายเดือนของทุกคน (หน้าภาพรวม และหน้าวันลา) รวมคำขอที่รออนุมัติ
- ตั้งค่าประเภทการลา: ได้รับค่าจ้างหรือไม่ และสิทธิ์ต่อปี
- เห็นสถานะการยืนยันวันทำงานของพนักงานแต่ละคนในงวดเงินเดือน และข้อความแจ้งแก้ไข (อนุมัติได้แม้ยังยืนยันไม่ครบ แต่ระบบจะเตือน)
- รางวัล: อนุมัติการแลกเงิน (เข้างวดเงินเดือนถัดไป), มอบ badge พิเศษ (พนักงานยอดเยี่ยม / ลูกค้าชม / Sushi Master), เพิกถอน, ปรับเงินรางวัลของแต่ละ badge และดูยอดค้างจ่ายรวม
- ประกาศถึงพนักงาน: ทุกสาขาหรือเฉพาะสาขา, ปักหมุด "สำคัญ", ตั้งวันหมดอายุ และดูว่าใครอ่านแล้ว/ยังไม่อ่าน
- ดู/แก้ไขการบันทึกเวลา: เพิ่มเวลาให้คนที่ลืมบันทึก หรือยกเลิกรายการผิด (บังคับใส่เหตุผล และเก็บประวัติว่าใครแก้)
- เงินเดือน: สร้างงวด (รายเดือนหรือกำหนดวันเอง) → คำนวณ → ปรับโบนัส/รายการหัก → อนุมัติ → บันทึกว่าจ่ายแล้ว (ล็อกงวด)
- Export CSV เปิดใน Excel ได้ (รองรับภาษาไทย)
- ตั้งค่าอัตรา OT, ประกันสังคม, ภาษี, ความแม่นยำ GPS

## การคิดเงินเดือน

| ประเภท | ค่าจ้างปกติ | ขาดงาน | มาสาย |
|---|---|---|---|
| รายเดือน | เงินเดือนเต็ม (คิดตามสัดส่วนถ้าเริ่มงานกลางงวด หรืองวดไม่เต็มเดือน) | หักวันละ เงินเดือน ÷ 30 | หักตามนาที |
| รายวัน | ค่าแรง × จำนวนวันที่มาทำงาน | ไม่ได้ค่าแรงวันนั้น | หักตามนาที |
| รายชั่วโมง | ค่าแรง × ชั่วโมงทำงานจริง | ไม่ได้ค่าแรง | ไม่หักซ้ำ (คิดตามเวลาจริงอยู่แล้ว) |

- **OT**: นับเวลาที่บันทึกออกหลังเลิกกะ ปัดลงทีละ 30 นาที คิด 1.5 เท่า
- **ทำงานวันหยุด**: รายเดือนได้เพิ่ม 1 เท่า รายวัน/รายชั่วโมงได้ 2 เท่า ส่วนที่เกินชั่วโมงปกติเป็น OT วันหยุดคิด 3 เท่า
- **วันลา**: ลาที่ได้รับค่าจ้างไม่ถูกหักเงิน (รายวัน/รายชั่วโมงได้ค่าแรงเต็มวัน) ส่วนลาไม่รับเงินหรือลาเกินสิทธิ์ต่อปี ถูกหักเหมือนขาดงาน (รายเดือน) หรือไม่ได้ค่าแรง (รายวัน/รายชั่วโมง)
- **การยืนยัน**: ถ้าผู้ดูแลแก้เวลาหรืออนุมัติลาหลังพนักงานยืนยันแล้ว ระบบคำนวณงวดใหม่อัตโนมัติ และถ้าตัวเลขเปลี่ยน พนักงานต้องยืนยันอีกครั้ง
- **รางวัล**:
  - badge ประเมินอัตโนมัติเมื่ออนุมัติงวดเงินเดือนที่จบสิ้นเดือน (ข้อมูลผ่านการยืนยันแล้ว)
  - ลาป่วยไม่เกิน 2 วัน/เดือน (ตั้งค่าได้) ไม่ตัดสิทธิ์ "ขยันเต็มเดือน"
  - เงินที่แลกเป็น "เงินได้ครั้งคราว": ไม่คิดประกันสังคม และหักภาษีเฉพาะส่วนเพิ่ม (ไม่คูณ 12)
  - ลาออก: ต้องจ่ายเงินคงเหลือในกระปุกก่อนปิดใช้งานพนักงาน
- **มาสาย**: ถ้าสายไม่เกินที่กำหนดในกะ (เช่น 5 นาที) จะไม่นับว่าสาย
- **ประกันสังคม**: 5% ของค่าจ้าง โดยมีฐานขั้นต่ำและเพดานตามที่ตั้งค่า
- **ภาษีหัก ณ ที่จ่าย**: ประมาณรายได้ทั้งปีจากงวดนี้ หักค่าใช้จ่าย 50% (ไม่เกิน 100,000), ลดหย่อนส่วนตัว 60,000, ประกันสังคม และค่าลดหย่อนเพิ่มเติมรายคน แล้วคิดอัตราขั้นบันไดและเฉลี่ยกลับเป็นรายงวด
- บันทึกครั้งเดียวทั้งวัน (ไม่ได้บันทึกออกพักเที่ยง) ระบบหักเวลาพักให้อัตโนมัติ

> ⚠️ อัตราประกันสังคม ภาษี และค่าแรงตามกฎหมายมีการเปลี่ยนแปลง ค่าเริ่มต้นในระบบเป็นเพียงตัวอย่าง (เช่น เพดานฐานค่าจ้างประกันสังคมตั้งไว้ 15,000 บาท)
> กรุณาตรวจสอบกับประกาศล่าสุดหรือนักบัญชี แล้วแก้ไขได้ที่หน้า **ตั้งค่า** ก่อนใช้จ่ายเงินจริง

## เทคโนโลยี

- [Next.js 15](https://nextjs.org/) (App Router + Server Actions) + React 19 + TypeScript
- [Prisma](https://www.prisma.io/) + PostgreSQL (อัปเดตโครงสร้างฐานข้อมูลด้วย migration ใน `prisma/migrations` — ไม่ลบข้อมูลเดิม)
- จำกัดการเดารหัสผ่าน: ใส่ผิด 5 ครั้งใน 15 นาที (ต่อบัญชี) หรือ 20 ครั้ง (ต่อ IP) ล็อก 15 นาที
- Session ใช้ JWT ใน httpOnly cookie (`jose`) และรหัสผ่านเก็บแบบ hash (`bcryptjs`)
- จำนวนเงินเก็บเป็น**สตางค์ (จำนวนเต็ม)** เพื่อหลีกเลี่ยงปัญหาทศนิยม
- รูปพนักงานถูกครอบเป็นสี่เหลี่ยมและย่อเหลือ 400×400 บนเครื่องก่อนส่ง แล้วเก็บในฐานข้อมูล (ไม่ต้องใช้ที่เก็บไฟล์แยก) เห็นได้เฉพาะเจ้าของรูปและผู้ดูแล
- สลิปเก็บผลคำนวณไว้ (snapshot) ข้อมูลเก่าไม่เปลี่ยนแม้ภายหลังจะปรับเงินเดือน

## ขึ้นใช้งานจริงบน Railway

แอพนี้ตั้งค่าไว้สำหรับ [Railway](https://railway.com) แล้ว (`railway.json`) ทุกครั้งที่ merge เข้า `main` จะ deploy ใหม่อัตโนมัติ
และระบบจะอัปเดตฐานข้อมูลเองตอนเริ่มทำงาน (`prisma migrate deploy`) โดยไม่ลบข้อมูลเดิม

> แพ็กเกจ Hobby ของ Railway ประมาณ $5/เดือน (ตรวจราคาล่าสุดที่หน้า Pricing ของ Railway)

### ครั้งแรก (ทำครั้งเดียว ประมาณ 20–30 นาที)

1. **สมัคร** ที่ [railway.com](https://railway.com) → **Login with GitHub** → เลือกแพ็กเกจ **Hobby** และผูกบัตร
2. **สร้างโปรเจกต์**: **New Project** → **Deploy from GitHub repo** → เลือก `Clock-in-and-out`
   (ถ้าไม่เห็น repo ให้กด **Configure GitHub App** แล้วอนุญาต repo นี้)
   — รอบแรกจะ deploy ไม่ผ่านเพราะยังไม่มีฐานข้อมูล เป็นเรื่องปกติ
3. **เพิ่มฐานข้อมูล**: ในหน้าโปรเจกต์กด **+ Create** (หรือ **+ New**) → **Database** → **PostgreSQL**
4. **ตั้งค่าตัวแปร**: คลิกกล่องของแอพ (`Clock-in-and-out`) → แท็บ **Variables** → **New Variable** เพิ่ม 3 ตัว

   | ชื่อ | ค่า |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (พิมพ์ `${{` แล้วเลือกจากรายการ) |
   | `AUTH_SECRET` | ข้อความสุ่มยาว ๆ อย่างน้อย 32 ตัว เช่น สร้างจาก [ตัวสุ่มรหัสผ่าน](https://1password.com/password-generator) ความยาว 40 ตัว — **ห้ามบอกใคร** |
   | `ADMIN_INITIAL_PASSWORD` | รหัสผ่านชั่วคราวของ admin อย่างน้อย 8 ตัว (ใช้ครั้งเดียวตอนเข้าครั้งแรก) |

   กด **Deploy** (หรือ **Apply changes**) แล้วรอให้สถานะเป็น **Active** (ประมาณ 2–4 นาที)
5. **สร้างลิงก์เว็บ**: แท็บ **Settings** → **Networking** → **Generate Domain** → จะได้ลิงก์ `https://….up.railway.app`
6. **เข้าใช้ครั้งแรก**: เปิดลิงก์ → รหัสพนักงาน `admin` + รหัสจาก `ADMIN_INITIAL_PASSWORD` → ระบบจะให้ตั้งรหัสผ่านใหม่ทันที
   (ถ้าไม่ได้ตั้ง `ADMIN_INITIAL_PASSWORD` ระบบจะสุ่มรหัสให้ ดูได้ที่แท็บ **Deployments** → **View logs**)

### ตั้งค่าร้านก่อนให้พนักงานใช้

- [ ] **ร้าน / สาขา**: เปิดหน้านี้**บนมือถือขณะยืนอยู่ในร้าน** แล้วกด “ใช้ตำแหน่งปัจจุบัน” → บันทึก
- [ ] **กะ / วันหยุด**: ตั้งเวลาทำงาน และเพิ่มวันหยุดนักขัตฤกษ์ของปี
- [ ] **ตั้งค่า**: ตรวจอัตรา OT ประกันสังคม (เพดานฐานค่าจ้าง) และภาษี กับประกาศล่าสุด
- [ ] **พนักงาน**: เพิ่มทุกคน พร้อมวันเริ่มงาน ค่าจ้าง และรหัสผ่านชั่วคราว (พนักงานจะตั้งรหัสใหม่เองตอนเข้าครั้งแรก)
- [ ] ส่งลิงก์ให้พนักงาน และบอกให้ **อนุญาต Location** และ **เพิ่มลงหน้าจอโฮม**
- [ ] แนะนำ: ทดลองกับ 1–2 คนก่อน 1 สัปดาห์ และใช้คู่กับระบบเดิม 1 เดือนเพื่อเทียบเงินเดือน

### หลังจากนั้น

- **อัปเดตแอพ**: merge PR ใน GitHub → Railway deploy ให้เอง (ข้อมูลไม่หาย)
- **ชื่อเว็บของร้านเอง** (ไม่บังคับ): Settings → Networking → **Custom Domain** แล้วตั้งค่า DNS ตามที่ Railway บอก
- **สำรองข้อมูล**: Export CSV เงินเดือนทุกเดือน และดูการสำรองฐานข้อมูลในหน้า PostgreSQL ของ Railway (แท็บ Backups)
- **ห้ามลบ** บริการ PostgreSQL ใน Railway — ข้อมูลทั้งหมดอยู่ในนั้น

## รันในเครื่อง (สำหรับทดลอง/พัฒนา)

ต้องมี Node.js 20 ขึ้นไป และฐานข้อมูล PostgreSQL หนึ่งตัวสำหรับทดลอง (แยกจากของจริงบน Railway) เลือกได้ 2 ทาง

- **ง่ายที่สุด**: สมัคร [Neon](https://neon.tech) (ฟรี) → สร้างโปรเจกต์ → คัดลอก **Connection string**
- หรือติดตั้ง PostgreSQL ในเครื่องเอง (Mac: [Postgres.app](https://postgresapp.com))

```bash
npm install
cp .env.example .env        # แล้วใส่ DATABASE_URL (จาก Neon) และ AUTH_SECRET
npm run setup               # สร้างตาราง + ข้อมูลทดลอง
npm run dev                 # เปิด http://localhost:3000
```

บัญชีทดลอง (เฉพาะ `npm run setup` ในเครื่อง — บน server จะไม่มีบัญชีเหล่านี้)

| รหัส | รหัสผ่าน | สิทธิ์ |
|---|---|---|
| `admin` | `admin1234` | ผู้ดูแลระบบ |
| `E001` | `1234` | พนักงานรายเดือน |
| `E002` | `1234` | พนักงานรายวัน |

**อัปเดตโค้ดในเครื่องหลัง merge**: `git pull` → `npm install` → `npm run db:deploy` → `npm run dev`

## โครงสร้างโปรเจกต์

```
prisma/schema.prisma      โครงสร้างฐานข้อมูล
prisma/migrations/        ประวัติการเปลี่ยนโครงสร้างฐานข้อมูล
prisma/seed.ts            ข้อมูลเริ่มต้น (server) / ข้อมูลทดลอง (--demo)
railway.json              ตั้งค่า build/start บน Railway
lib/geo.ts                คำนวณระยะ (Haversine)
lib/attendance.ts         จับคู่เข้า/ออก → สรุปรายวัน (สาย, OT, ขาด)
lib/payroll.ts            สูตรคำนวณเงินเดือน, ประกันสังคม, ภาษี
lib/payroll-service.ts    คำนวณงวดเงินเดือนจากฐานข้อมูล
app/actions/clock.ts      บันทึกเวลา + ตรวจพื้นที่ร้าน (server)
app/clock, app/history, app/payslips   หน้าพนักงาน
app/admin/*               หน้าผู้ดูแลระบบ
tests/*                   unit tests
```

## ข้อจำกัด และสิ่งที่ควรทำต่อ

- **การปลอม GPS**: Web App ป้องกันแอพ Fake GPS ไม่ได้ 100% ระบบจึงเก็บพิกัด ความแม่นยำ และอุปกรณ์ทุกครั้งเพื่อตรวจย้อนหลัง
  ถ้าต้องการเข้มงวดขึ้น ควรเพิ่มถ่ายเซลฟี่ตอนบันทึกเวลา หรือทำเป็นแอพ native ที่ตรวจ mock location / Wi-Fi ร้านได้
- OT นับอัตโนมัติจากเวลาบันทึกออก ยังไม่มีขั้นตอนขออนุมัติ OT
- ยังไม่รองรับการลาครึ่งวัน และการแนบใบรับรองแพทย์
- แจ้งเตือนประกาศจะเห็นเมื่อเปิดแอพ ยังไม่มี push notification ตอนปิดแอพ
- ยังไม่มีไฟล์ส่งประกันสังคม, ภ.ง.ด.1, ไฟล์โอนเงินธนาคาร และการแจ้งเตือนผ่าน LINE
- ข้อมูลตำแหน่งและเงินเดือนเป็นข้อมูลส่วนบุคคล ควรแจ้งพนักงานตาม PDPA
